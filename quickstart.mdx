This guide walks you through the fastest path from zero to a working RAG knowledge base: clone the repo, set a handful of environment variables, start the stack with Docker Compose, and send your first question. The whole flow takes about five minutes once the images are pulled. You will need [Docker](https://www.docker.com/), [Docker Compose](https://docs.docker.com/compose/), [Git](https://git-scm.com/), and credentials for at least one LLM provider (or a local Ollama installation).

<Steps>

  <Step title="Clone the Repository">
    Clone WeKnora and enter the project directory:

    ```bash
    git clone https://github.com/Tencent/WeKnora.git
    cd WeKnora
    ```
  </Step>

  <Step title="Copy and Open .env">
    The repository ships with a fully-commented example file. Copy it to `.env`—the name the Docker Compose file expects:

    ```bash
    cp .env.example .env
    ```

    Open `.env` in your editor. The next step covers the required variables.
  </Step>

  <Step title="Set Required Environment Variables">
    At minimum, set these five variables before starting the stack. All other variables have safe defaults for local use.

    **Security keys** — generate once and keep them safe:

    ```bash
    # Paste the output of each command into .env
    openssl rand -hex 32   # → JWT_SECRET
    openssl rand -hex 16   # → SYSTEM_AES_KEY  (must be exactly 32 ASCII characters)
    ```

    ```ini
    # .env — required section
    JWT_SECRET=<paste openssl rand -hex 32 output here>
    SYSTEM_AES_KEY=<paste openssl rand -hex 16 output here>
    ```

    **Database credentials** — change the defaults before any network-accessible deployment:

    ```ini
    DB_USER=postgres
    DB_PASSWORD=postgres123!@#
    DB_NAME=WeKnora
    REDIS_PASSWORD=redis123!@#
    ```

    **LLM connection** — set at least one of the following:

    <Tabs>
      <Tab title="Ollama (local)">
        If Ollama is already running on your host machine, no additional `.env` changes are needed—the default `OLLAMA_BASE_URL=http://host.docker.internal:11434` points there automatically. Start Ollama if it is not already running:

        ```bash
        ollama serve > /dev/null 2>&1 &
        ollama pull qwen3:8b          # example chat model
        ollama pull nomic-embed-text  # example embedding model
        ```

        <Note>
          `host.docker.internal` resolves to the Docker host on both macOS and Windows. On Linux, the `extra_hosts: host.docker.internal:host-gateway` entry in `docker-compose.yml` provides the same resolution automatically.
        </Note>
      </Tab>
      <Tab title="OpenAI-compatible API">
        Any OpenAI-compatible provider (OpenAI, DeepSeek, SiliconFlow, etc.) can be configured through the **Settings → Models** page in the UI after first login. You do not need to add API keys to `.env` in advance—they are stored encrypted in the database.
      </Tab>
    </Tabs>
  </Step>

  <Step title="Pull Images">
    Pull all images matching the `WEKNORA_VERSION` in your `.env` (defaults to `latest`):

    ```bash
    docker compose pull
    ```

    This step downloads the `weknora-app`, `weknora-ui`, `weknora-docreader`, ParadeDB, and Redis images. Expect 2–4 GB on first pull.
  </Step>

  <Step title="Start Core Services">
    Start all core services in detached mode:

    ```bash
    docker compose up -d
    ```

    Watch service health until everything is ready:

    ```bash
    docker compose ps
    ```

    All services should report `healthy` or `running` within 60–90 seconds. You can verify the backend specifically:

    ```bash
    curl http://localhost:8080/health
    # {"status":"ok"}
    ```
  </Step>

  <Step title="Open the Web UI">
    Open **[http://localhost](http://localhost)** in your browser. The full service URL map is:

    | Service | URL |
    |---------|-----|
    | Web UI | `http://localhost` |
    | Backend API | `http://localhost:8080` |
    | Langfuse Tracing | `http://localhost:3000` _(requires `--profile langfuse`)_ |

    On the first visit you will see a registration page. Register an account—WeKnora has no pre-created admin account. After registering, your account becomes the Owner of an automatically created personal workspace.

    <Tip>
      To bootstrap a system administrator (for platform-level settings), register your account first, then add `WEKNORA_BOOTSTRAP_SYSTEM_ADMIN_EMAIL=your@email.com` to `.env` and run `docker compose up -d app`. This only promotes the user on startup if no system admin exists yet.
    </Tip>
  </Step>

  <Step title="Create a Knowledge Base">
    In the sidebar, click **Knowledge Bases → New**. Give it a name and choose the type:

    - **Document** — for PDF, Word, Markdown, and other file-based content.
    - **FAQ** — for structured question–answer pairs.

    The initialization wizard opens automatically. Select your chat model and embedding model, then click **Test** to verify connectivity before saving.
  </Step>

  <Step title="Upload a Document">
    Inside the knowledge base, drag a file into the upload area or paste a URL. Supported formats include PDF, Word, Excel, PowerPoint, Markdown, HTML, EPUB, images, and audio files.

    The document goes through asynchronous parsing: `pending → processing → finalizing → completed`. Large PDFs and scanned documents take longer. The document list refreshes in real time.

    <Note>
      The default file size limit is 50 MB (`MAX_FILE_SIZE_MB`). The default per-document processing timeout is 2 hours (`WEKNORA_DOCUMENT_PROCESS_TIMEOUT`). Both are adjustable in `.env`.
    </Note>
  </Step>

  <Step title="Ask a Question">
    Open the **Chat** view, select your knowledge base, and type a question. The default **Quick Q&A** agent retrieves relevant chunks and generates a grounded answer with inline source citations. Click any citation to view the original passage.

    You can also use the API directly:

    ```bash
    BASE=http://localhost:8080/api/v1

    # 1. Login and capture the token
    LOGIN=$(curl -s -X POST $BASE/auth/login \
      -H "Content-Type: application/json" \
      -d '{"email":"you@example.com","password":"yourpassword"}')
    TOKEN=$(echo $LOGIN | jq -r '.token')
    KB_ID=<your-knowledge-base-id>

    # 2. Create a session
    SESSION_ID=$(curl -s -X POST $BASE/sessions \
      -H "Authorization: Bearer $TOKEN" \
      -H "Content-Type: application/json" \
      -d '{"title":"First session"}' | jq -r '.data.id')

    # 3. Ask a question (SSE streaming response)
    curl -N -X POST $BASE/knowledge-chat/$SESSION_ID \
      -H "Authorization: Bearer $TOKEN" \
      -H "Content-Type: application/json" \
      -d "{\"query\":\"What does this document cover?\",\"knowledge_base_ids\":[\"$KB_ID\"]}"
    ```
  </Step>

</Steps>

## Optional Service Profiles

The core stack runs without any profiles. Add `--profile` flags to enable additional components. Multiple profiles can be combined.

| Profile | Adds | When to use |
|---------|------|-------------|
| _(default)_ | app, frontend, docreader, postgres, redis | All local and production deployments |
| `neo4j` | Neo4j graph database | Enable GraphRAG (`NEO4J_ENABLE=true`) |
| `minio` | MinIO object storage | Store files in S3-compatible storage instead of the local volume |
| `langfuse` | Langfuse + ClickHouse + dedicated MinIO | LLM call tracing and token usage dashboards |
| `full` | Neo4j, MinIO, Qdrant, SearXNG, Langfuse stack, sandbox, MCP server, and Dex | Enable every optional feature at once |

```bash
# Example: enable Neo4j and MinIO
docker compose --profile neo4j --profile minio pull
docker compose --profile neo4j --profile minio up -d

# Stop everything
docker compose down
```

## Upgrading

When a new WeKnora release is available, set the target version in `.env` and re-pull:

```bash
# In .env, set: WEKNORA_VERSION=v0.8.2
docker compose pull
docker compose up -d
```

<Warning>
  Running `docker compose up -d` without `pull` reuses locally cached images and may leave the UI version out of sync with the backend. Always run `docker compose pull` first when upgrading. Keep your existing `SYSTEM_AES_KEY` unchanged on upgrade—changing it makes all previously encrypted credentials unreadable.
</Warning>
